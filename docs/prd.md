## 1. 产品概述

### 1.1 产品背景

随着大语言模型技术的成熟，企业迫切需要一套能够将 AI 能力转化为实际业务价值的平台。当前市场上的 Agent 平台要么过于面向开发者（如 LangChain/LangGraph），要么功能单一（如 n8n），要么缺乏企业级特性（如 OpenClaw）。

ChatBiz Agent Platform 汲取 DeerFlow、Dify、Hermes 等平台的优点，打造一款**面向企业的可视化 AI Agent 编排平台**，让业务人员和技术人员都能高效构建和部署智能体应用。

### 1.2 产品愿景

> 让企业中的每一位员工都能轻松构建和部署 AI 智能体，实现业务流程的智能化升级。

### 1.3 核心价值主张

| 价值点 | 描述 |
|--------|------|
| **低门槛编排** | 可视化拖拽 + 代码化编排的混合模式，兼顾业务人员和技术人员 |
| **企业级安全** | RBAC 权限、数据隔离、审计日志、沙箱执行，满足企业合规要求 |
| **灵活扩展** | MCP 标准化协议 + 自定义插件，无缝对接企业现有系统 |
| **全链路可观测** | 从工作流设计到运行监控的完整可观测性 |

## 2. 目标用户与场景

### 2.1 用户画像

| 用户角色 | 技术能力 | 核心诉求 | 使用场景 |
|---------|---------|---------|---------|
| **业务人员** | 低 | 快速搭建 AI 应用，无需编程 | 使用可视化画布搭建客服机器人、文档问答 |
| **AI 开发者** | 中高 | 灵活编排复杂逻辑，调试优化 | 代码化编排、自定义节点、模型调优 |
| **平台管理员** | 高 | 系统管理、权限控制、资源监控 | 用户管理、权限配置、系统监控 |
| **企业开发者** | 高 | 集成企业内部系统，二次开发 | API 调用、插件开发、企业系统集成 |

### 2.2 典型使用场景

**场景一：智能客服机器人**
- 业务人员通过可视化画布拖拽节点，连接知识库和 LLM
- 配置多轮对话流程，设置转人工条件
- 一键发布到企业微信/钉钉/网页

**场景二：数据分析助手**
- 开发者编写自定义代码节点，连接企业数据库
- 配置 Agent 自主推理流程，自动分析数据并生成报告
- 设置定时触发，每日自动推送分析结果

**场景三：合同审核助手**
- 上传合同文档到知识库
- 配置 RAG 检索 + LLM 审核流程
- 设置人工审批节点，AI 初审后转人工复核

**插件核心接口**：

```python
# plugin.py - 插件入口类示例
from chatbiz_sdk import Plugin, Tool, ToolParameter

class MySQLPlugin(Plugin):
    """MySQL 数据库插件"""
    
    def __init__(self, config: dict):
        super().__init__(config)
        self.connection_pool = None
        
    async def on_init(self):
        """插件初始化时调用"""
        self.connection_pool = await create_pool(
            host=self.config['host'],
            port=self.config.get('port', 3306),
            database=self.config['database'],
            user=self.config['username'],
            password=self.config['password'],
            max_size=self.config.get('max_connections', 20)
        )
        
    async def on_destroy(self):
        """插件卸载时调用"""
        if self.connection_pool:
            await self.connection_pool.close()
            
    @Tool(
        name="query",
        description="执行 SQL 查询",
        parameters=[
            ToolParameter(name="sql", type="string", required=True),
            ToolParameter(name="params", type="array", required=False)
        ]
    )
    async def query(self, sql: str, params: list = None) -> dict:
        """执行查询并返回结果"""
        # SQL 安全审核
        self._validate_sql(sql)
        
        async with self.connection_pool.acquire() as conn:
            async with conn.cursor() as cursor:
                await cursor.execute(sql, params)
                rows = await cursor.fetchall()
                columns = [desc[0] for desc in cursor.description]
                return {
                    "columns": columns,
                    "rows": rows,
                    "rowCount": len(rows),
                    "executionTime": cursor.execution_time
                }
                
    def _validate_sql(self, sql: str):
        """SQL 安全审核"""
        forbidden = self.config.get('forbidden_keywords', [])
        for keyword in forbidden:
            if keyword.upper() in sql.upper():
                raise SecurityError(f"禁止执行的 SQL: {keyword}")
```

**交互说明**：

**左侧：任务分类列表**
- **任务分类管理**：用户可自主创建属于自己的任务分类（如「TreeProject」「ChatBiz」），任务分类支持共享给团队成员，实现协作
- **分类层级展示**：左侧以树形结构展示任务分类及其下的任务项，支持展开/折叠分类
- **新建任务**：顶部「+新建任务」按钮快速创建新任务；每个分类右侧悬浮「+」按钮可在该分类下直接新建任务
- **快捷导航**：顶部提供「技能」「自动化」快捷入口，方便用户快速切换功能模块
- **任务列表操作**：支持分类排序、搜索筛选等操作
- **当前任务高亮**：当前选中的任务项高亮显示，左侧带品牌色边框标识

**中间：智能对话区域**
- **零配置智能对话**：用户无需手动选择 Agent、Skill、工具或工作流，只需像聊天一样自然输入，系统自动完成一切
- **智能意图识别**：Lead Agent 自动分析用户输入的意图，自动委派给最合适的 Sub-Agent，并自动加载绑定的 Skill、插件和知识库
- **Skill 自动加载展示**：Agent 被委派后，系统自动加载其绑定的 Skill，在对话顶部以标签形式展示已加载的技能（如「数据分析」「SQL查询」「图表生成」），用户可点击展开查看 Skill 详情或手动添加/移除技能
- **上下文感知工具调用**：Agent 根据对话上下文自动判断是否需要调用工具（数据库查询、文件操作、API 调用等），无需用户手动选择「工具」
- **智能工作流触发**：当任务复杂度超过单轮对话处理能力时，Agent 自动在后台触发工作流执行，用户只需等待结果
- **智能推荐快捷操作**：Agent 回复后，根据上下文自动推荐下一步操作按钮（如「查看详细报表」「导出 Excel」「预测下月趋势」），用户一键点击即可执行
- **智能追问引导**：当信息不足时，Agent 自动给出追问建议（如「请提供时间范围：[本月] [本季度] [本年]」），用户一键选择即可回复
- **工作流执行可视化**：工作流在后台自动触发时，对话中以折叠卡片形式显示执行进度，完成后自动展开展示结果
- **多 Agent 协作透明化**：多 Agent 协作过程以时间线形式展示在对话中，用户可展开查看每个 Agent 的执行细节
- **对话区域支持 Markdown 渲染、代码高亮、表格展示**
- **支持对话导出为 Markdown/PDF**
- **高级模式**：点击顶部「⚙️」可切换为手动模式，手动选择 Agent/工作流/工具（面向高级用户）

**右侧：任务信息面板**
- **待办清单**：展示当前会话的待办事项列表，完成的任务项显示打钩标记和删除线，支持添加、编辑、删除待办项
- **任务产物**：展示本次会话产生的输出文件（如 HTML、Markdown、Excel 等），点击可预览或下载文件
- **参考信息**：自动记录任务执行过程中调用的技能和参考的网页链接，以列表形式展示，方便用户追溯信息来源；无参考信息时显示空状态提示

**模型切换**：
- 顶部右侧显示当前使用的模型（如「GPT-4o ▼」），点击展开下拉菜单，可快速切换已配置的模型（GPT-4o、Claude 3.5、DeepSeek-V3、ERNIE 4.0 等）
- 切换模型后，当前对话上下文保留，后续回复使用新模型生成
- 下拉菜单底部提供「模型管理」入口，跳转模型配置页面

**附件功能**：
- 输入框左侧提供「附件」「图片」「语音」三个按钮
- 点击「附件」可上传本地文件（支持 Excel、PDF、Word、图片等格式），上传后在输入框上方显示文件列表预览，带文件名和删除按钮
- 附件随消息一起发送，Agent 自动解析附件内容并纳入上下文
- 支持拖拽文件到对话区域直接上传
- 已上传的附件在对话中显示为可点击的文件卡片，支持下载和预览

- **智能意图识别**：Lead Agent 自动分析用户输入的意图，自动委派给最合适的 Sub-Agent，并自动加载绑定的 Skill、插件和知识库
- **大圆角输入框**：底部输入区域采用大圆角（rounded-2xl）设计，内部包含多行文本域（textarea），支持多行输入和自动换行

- **语音输入**：语音按钮（🎤）位于发送按钮左侧，点击开始语音输入，再次点击结束并自动发送
- **附件功能**：点击附件图标（📎）上传文件，上传后在输入框上方显示文件列表预览（带文件名和删除按钮）；支持 Excel、PDF、Word、图片等格式
- **Skill 自动加载展示**：Agent 被委派后，系统自动加载其绑定的 Skill，在对话顶部以标签形式展示已加载的技能（如「数据分析」「SQL查询」「图表生成」）；输入框下方也展示「已加载技能」标签列表，用户可点击移除
- **上下文感知工具调用**：Agent 根据对话上下文自动判断是否需要调用工具（数据库查询、文件操作、API 调用等），无需用户手动选择「工具」
- **智能工作流触发**：当任务复杂度超过单轮对话处理能力时，Agent 自动在后台触发工作流执行，用户只需等待结果
- **智能推荐快捷操作**：Agent 回复后，根据上下文自动推荐下一步操作按钮（如「查看详细报表」「导出 Excel」「预测下月趋势」），用户一键点击即可执行
- **智能追问引导**：当信息不足时，Agent 自动给出追问建议（如「请提供时间范围：[本月] [本季度] [本年]」），用户一键选择即可回复
- **工作流执行可视化**：工作流在后台自动触发时，对话中以折叠卡片形式显示执行进度，完成后自动展开展示结果
- **多 Agent 协作透明化**：多 Agent 协作过程以时间线形式展示在对话中，用户可展开查看每个 Agent 的执行细节
- **对话区域支持 Markdown 渲染、代码高亮、表格展示**
- **支持对话导出为 Markdown/PDF**
- **高级模式**：点击顶部「⚙️」可切换为手动模式，手动选择 Agent/工作流/工具（面向高级用户）

### 7.3 关键实现方案

#### 7.3.1 可视化画布到 LangGraph 的编译

```
画布 JSON → 解析器 → StateGraph 定义 → 编译 → 可执行图

画布 JSON 结构:
{
  "nodes": [
    { "id": "start", "type": "start", "position": {x, y} },
    { "id": "llm_1", "type": "llm", "config": {...} },
    { "id": "end", "type": "end", "position": {x, y} }
  ],
  "edges": [
    { "source": "start", "target": "llm_1" },
    { "source": "llm_1", "target": "end" }
  ]
}

编译过程:
1. 遍历节点，为每个节点生成对应的 LangGraph 节点函数
2. 遍历边，添加普通边或条件边
3. 定义 State 结构（TypedDict）
4. 编译为可执行的 CompiledGraph
```

#### 7.3.2 Agent 执行流程

```
用户输入
    │
    ▼
[Context Assembly]  ← 组装系统提示词 + 历史对话 + 工具描述
    │
    ▼
[Prompt Build]  ← 构建完整 Prompt
    │
    ▼
[LLM Inference]  ← 调用 LLM
    │
    ├──→ [Direct Reply] → 输出结果
    │
    └──→ [Tool Call] → [Tool Execute] → [Result Format]
                              │
                              ▼
                        [LLM Inference] ← 循环直到完成
                              │
                              ▼
                        [Output Stream]
```

#### 7.3.3 记忆管理流程

```
用户输入
    │
    ▼
[记忆检索]  ← 从四层记忆中检索相关信息
    │
    ├──→ L1 工作记忆（内存）

    ├──→ L3 长期记忆（PostgreSQL）
    └──→ L4 语义记忆（向量数据库）
    │
    ▼
[上下文组装]  ← 将检索到的记忆注入 Prompt
    │
    ▼

    │
    ▼
[记忆更新]  ← 更新各层记忆
    │
    ├──→ 更新工作记忆

    ├──→ 更新长期记忆（关键信息）

```
